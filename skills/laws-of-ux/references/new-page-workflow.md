# Plan a new page

Use this workflow for a brief, wireframe, page specification, or design direction before implementation.

## Define the job

Start from the audience, their reason for arriving, the main task they need to complete, and the page's role in the wider journey. Reuse supplied research and product constraints. If these are unknown, state assumptions instead of presenting guesses as user facts.

## Shape the page

1. **Set the hierarchy:** order the information by what users need to understand and decide first. Give the main action a clear label and visual priority; keep secondary actions distinct.
2. **Reduce avoidable effort:** group related content, use plain labels, and simplify or stage choices when that helps the task. Do not hide important options merely to make the page look sparse.
3. **Use recognizable patterns:** use conventions that help users predict the result of an action, while respecting this product's mental model and audience.
4. **Specify behavior:** describe navigation, controls, form validation, loading and status feedback, empty and error states, and recovery—not only the default visual state.
5. **Design across contexts:** account for narrow screens, keyboard use, focus visibility, semantic structure, readable contrast, and zoom/reflow as part of the design, not a later polish pass.
6. **Explain consequential choices:** name the relevant UX principle only when it explains why a design may help. Note tradeoffs and what should be validated with users.

## Deliverable

For a lightweight request, provide a page outline and the main interaction. For a fuller specification, include:

- audience, task, assumptions, and constraints;
- ordered sections and key content;
- primary and secondary actions with expected outcomes;
- key interaction and recovery states;
- responsive and accessibility considerations;
- open questions or a simple usability task for validation.

Do not claim that a principle guarantees conversion, comprehension, or completion. When research is absent, frame the blueprint as a reasoned starting point and name the most important assumption to test.
